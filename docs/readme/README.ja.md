**HTML Merge** は、WinMerge のように 2 つのフォルダーまたは 2 つのファイルを左右に並べて
比較します。ただし、Windows、macOS、Linux、ChromeOS、Android、iOS のあらゆる最新ブラウザー
で動作する、1 つの HTML ファイルです。2 つのフォルダーを選ぶと、両方のすべてのファイルにつ
いて、同一・異なる・左のみ・右のみという結果の一覧が表示されます。ファイルを開くと、2 つの
バージョンが左右に並び、40 以上の言語に対応した構文ハイライト、変更された行内で変更された
単語の強調表示、そしてスクロールバーの横にすべての差分の位置を示すマップが表示されます。

読み取り専用です。何もインストールされず、何もアップロードされず、ファイルが変更されること
もありません。ファイルはこのページ自体がブラウザー内で読み込むだけで、このページはネット
ワークに一切アクセスできません。

同じページは PWA（プログレッシブウェブアプリ）としても動作します。GitHub Pages から配信さ
れたものはシステムにインストールでき、独自のウィンドウとアイコンを持つ別アプリとして動作
し、オフラインでも使えます——「[GitHub Pages](#github-pages)」を参照してください。

**オンラインデモ： [merge.marketkernel.com](https://merge.marketkernel.com/)**

![HTML Merge: JavaScript ファイルの 2 つのバージョンを左右に並べたところ](../html-merge.png)

## 使い方

1. `build/html-merge.html` をビルドする（「[ビルド](#ビルド)」を参照）か、リリースから入
   手して、ブラウザーで開きます——ディスクから直接開いても構いません。
2. 左側と右側をそれぞれ選びます：**フォルダー…** または **ファイル…**、あるいはフォルダー
   やファイルを対応するボックスにドラッグします。2 つのフォルダーまたは 2 つのファイルを一
   度にウィンドウへドロップすると、すぐに比較が始まります。
3. **比較** を押します。

2 つのフォルダーを選ぶと、ファイルの比較が進むにつれてフォルダー一覧が表示され、内容が埋ま
っていきます。上部のチップで各結果の種類を表示・非表示にしたり件数を確認したりできます。一
覧はツリー表示にもフラットなパス一覧にもでき、名前（`util` や `*.ts` のようなパターン）で
絞り込み、任意の列で並べ替えられます。ファイルをダブルクリックする（または選択して Enter
を押す）と比較が開始されます。`]` と `[` で次と前の異なるファイルへ移動し、Esc またはブラ
ウザーの戻るボタンで一覧に戻ります。

ファイル画面では：

- 矢印（Alt+↓ と Alt+↑、または F7 と Shift+F7）で差分間を移動します。現在の差分は行番号欄
  に示され、右側のマップにすべての差分の位置が表示されます——クリックするとジャンプします。
- **左右表示または上下表示** で、2 つのペインと 1 つの統合ペインを切り替えます。
- **同一行を折りたたむ** は、長く同一な部分を隠し、各差分の前後に数行だけ残します。折りた
  たみ部分をクリックすると開きます。
- **検索**（Ctrl+F、Mac では ⌘F）は両側のすべての一致箇所を強調表示します。Enter と
  Shift+Enter で一致箇所間を移動します。
- **⋯** メニューには表示と比較のオプションがあります：レイアウト、ファイルを着色する言語、
  構文の配色、空白文字と改行コードの表示、変更された行内を単語単位か文字単位で示すか、そし
  て何を無視するか。

画像（PNG、JPEG、GIF、WebP、BMP、ICO、AVIF）はピクセルサイズとともに左右に並べて表示され
ます。その他のバイナリファイルはバイト単位で比較され、同一かどうか、最初の差分の位置、そし
てその周囲のバイトが表示されます。

Chrome と Edge は最近の比較を記憶します。それらは開始画面に一覧表示され、クリックすると再
度開けます（ブラウザーはフォルダーを読み取る許可をもう一度確認します）。他のブラウザーでは
毎回フォルダーを選び直す必要があります。

### スマートフォンでは

このページはスマートフォンの画面でも動作します。開始画面では両側が縦に重なって表示され、フ
ォルダー一覧には名前と結果が残り、ファイルのペアは上下に表示されます。ファイルをタップする
と開きます。Android では Chrome がフォルダーとファイルの両方を選択できます。iOS ではファイ
ルの比較はできますが、フォルダーは選択できません。

## 機能

- **フォルダー**：内容による再帰的な比較（より高速なサイズと日付による比較も可能）。ツリー
  表示またはフラット表示。結果と名前によるフィルター。名前、結果、サイズ、日付による並べ替
  え。パターンによる名前の除外（`.git; node_modules; *.log; build/`）。ファイル名の大文字
  小文字を区別するかどうかの選択。ファイルを読み込みながら少しずつ結果が埋まっていくので、
  大きなフォルダーでもすぐに何かが表示されます。
- **テキスト**：Myers のアルゴリズムに patience diff を組み合わせているため、移動した括弧
  や空行が無関係なコードと誤って対応付けられません。変更されたブロック内の行は類似度に応じ
  て対応付けられます。行内で変更された単語や文字が強調表示されます。空行のまとまりは無視で
  きます。統合表示、同一行の折りたたみ、両側を対象にした検索にも対応します。
- **比較オプション**：空白の変化または空白全体の無視、大文字小文字の無視、空行の無視、改行
  コード（CRLF、LF、CR）の無視——フォルダー一覧とファイル画面の両方に適用されます。
- **エンコーディング**：UTF-8、BOM 付き UTF-8、UTF-16 LE および BE、そして有効な UTF-8 で
  ないファイル用の Windows-1252。各側のエンコーディング、改行コード、行数が表示され、改行
  コードのみが異なる場合はそのように示されます。
- 40 以上の言語に対応した **構文ハイライト**。ファイル名または先頭行
  （`#!/usr/bin/env python3`）で自動判定されます：JavaScript、TypeScript、JSON、HTML
  （内部のスクリプトとスタイルを含む）、XML、CSS、SCSS、Less、Markdown、Python、Java、
  Kotlin、C、C++、C#、Go、Rust、Swift、Objective-C、PHP、Ruby、シェル、PowerShell、バッ
  チファイル、SQL、YAML、TOML、INI、Dockerfile、Makefile、CMake、diff、Lua、Perl、R、
  Dart、Scala、Groovy、Haskell、Elixir、GraphQL、Protocol Buffers、Pascal、Visual Basic。
  その他の言語も手動で選択できます。
- **大きなファイル**：画面に見えている行だけを描画するため、数十万行のファイルでもスムーズ
  にスクロールできます。非常に長い行は画面上で省略されます（比較自体は全体を見ます）。
- 上記のとおりの **画像とバイナリファイル** の比較。
- インターフェースは **17 言語** に対応し、アラビア語とウルドゥー語は右から左に表示されま
  す。ライトテーマとダークテーマがあり、システムに従うか手動で選べます。
- インストールされたアプリは、確認された場合にのみ更新されます。
  「[GitHub Pages](#github-pages)」を参照してください。

## セキュリティ

- **読み取り専用。** このページはファイルを読み取るだけで、書き込み、名前の変更、削除は一
  切行いません。Chrome と Edge では、フォルダーは File System Access API を通じて読み取り
  専用でアクセスされます。
- **構造上オフライン。** このページの Content-Security-Policy は `connect-src 'none'` を
  指定しており、必要なもの——スタイル、コード、アイコン——はすべてこの 1 つの HTML ファイル
  の中に含まれています。比較するファイルに何が含まれていても、何かを読み込んだり送信したり
  することはできません。
- **固定されたスクリプト。** ビルド時に `script-src 'unsafe-inline'` が、ページ内の唯一の
  スクリプトのハッシュ値に置き換えられます。万が一ファイル名やテキストの 1 行がエスケープ
  されずに紛れ込んでも、その中のインラインハンドラーが実行されることはありません。ファイル
  からのテキストはエスケープされた状態でページに渡されます。
- 最近の比較（Chrome と Edge）は、ブラウザーの IndexedDB にフォルダーのハンドルのみを保存
  します——ファイル名も内容も含まれません。設定は `localStorage` に保存されます。

## 翻訳

インターフェースは英語、中国語、ヒンディー語、スペイン語、フランス語、アラビア語、ベンガル
語、ポルトガル語、ロシア語、ウルドゥー語、インドネシア語、ドイツ語、日本語、マラーティー
語、テルグ語、トルコ語、ウクライナ語に対応しています。ブラウザーの言語設定の中で最初に見つ
かった対応言語で起動し、「設定 → 言語」で別の言語を選べます。

- 英語のテキストはコード内にあります：`t('context', 'English text')`、数字を含むテキスト
  には `tn('context', '{count} file', '{count} files', n)` を使います。
  `src/app/template.html` では、同じことを `data-i18n="context"`（要素のテキスト）と
  `data-i18n-attr="context"`（title、placeholder、aria-label）で行います。
- 他の各言語は辞書ファイル `src/locales/<code>.json` です：
  `{ "context": { "English text": "translation" } }`。数字を含むテキストには、その言語の
  複数形カテゴリー（`Intl.PluralRules`）ごとに 1 つの形があり、英語の複数形をキーとします。
- 辞書にない項目は英語で表示されます。
- `npm run i18n` は、言語ごとに辞書に不足している文字列と、インターフェースでもう使われて
  いないのに辞書に残っている文字列を出力します。`npm test` はプレースホルダーと複数形を検
  証します。

## ビルド

Node.js 20 以降が必要です。

```sh
npm install
npm run build        # build/html-merge.html and build/pages/
npm run watch        # rebuilds on every change
npm run check        # typecheck, unit tests, build, browser tests
```

`./build.sh` は `npm run build` と同じことを行い、初回実行時に依存関係をインストールしま
す。依存関係は esbuild と TypeScript だけで、どちらもビルド用です。ページ自体はライブラリ
を一切使用しません。

- `npm test` は Node 上でユニットテストを実行します：差分、行と折りたたみ、エンコーディン
  グ、ハイライターとその文法、フォルダー比較、辞書。
- `npm run test:browser` は、DevTools プロトコル経由でヘッドレス Chrome を使い、ビルドさ
  れたページと PWA を操作します。他の依存関係は不要ですが、ローカルの Chrome または
  Chromium が必要で（`CHROME=/path/to/chrome` で指定可能）、見つからない場合はスキップさ
  れます。
- `npm run shots -- <dir>` は、主要な各画面のスクリーンショットを保存します。
- `npm run icons` は `assets/icon.svg` から PWA の PNG アイコンを生成します。

## バージョンとリリース

バージョン番号は `package.json` にのみ存在します。`v<version>` タグが付いたコミットのビル
ドはそのまま表示されますが、それ以外のビルドにはコミットが付加され（例：
`0.1.0+1a2b3c4`）、`main` からビルドされたページがリリース版と誤認されないようになってい
ます。バージョンは開始画面の下部と設定画面に表示されます。

リリース手順：`npm version minor`（または `patch`）を実行し、続けて
`git push --follow-tags` を実行します。このタグによって
`.github/workflows/release.yml` が開始され、タグが `package.json` と一致するか確認し、テ
ストを実行したうえで、`html-merge-v<version>.html` と `SHA256SUMS.txt` を GitHub のリリー
スに添付します。

## GitHub Pages

このリポジトリの公開先： <https://merge.marketkernel.com/>

`build/pages/` は、インストール可能な PWA としての同じページです。マニフェスト、アイコ
ン、そしてオフラインでも動作し続けるための service worker が含まれます。
`.github/workflows/pages.yml` は `main` へのすべてのプッシュでビルドとテストを行い、
GitHub Pages にデプロイします（設定 → Pages → ソース：GitHub Actions）。パスはすべて相対
パスなので、プロジェクトサイトの `/<repo>/` というアドレス配下でも動作します。

- PWA の CSP は、マニフェスト、worker、アイコンのために自身のオリジンだけを追加します。
  `connect-src` は引き続き `'none'` のままです。
- 新しいデプロイは、実行中のバージョンを自動的に置き換えることはありません。新しい service
  worker は待機し、設定画面（と開始画面）に「バージョン X の準備ができました。更新」と表示
  されます。ページは 6 時間ごと、および接続が回復したときに、静かに確認を行います。
- 更新後、「バージョン X に更新しました」と一度だけ表示されます。

## 制限事項

- **設計上、読み取り専用**：マージも編集もできません。変更はお使いのエディターでコピーして
  ください。
- Firefox と Safari では、ブラウザー標準のフォルダーアップロードダイアログでフォルダーを選
  択します。フォルダー全体を一度に読み込み（除外対象の名前は読み込んだ後で除かれます。読み
  込み自体はスキップされません）、空のフォルダーは表示されず、再読み込みしてもその後追加さ
  れたファイルは反映されません——反映するにはフォルダーを選び直してください。iOS ではフォル
  ダーを選択すること自体ができません。
- 64 MB を超えるファイルは、無視オプションなしでバイト単位のみで比較されます。
- 構文ハイライトは字句解析によるもので——キーワード、文字列、コメント、数値——構文解析器で
  はありません。一部の構造（JSX タグ、ヒアドキュメントなど）は普通のテキストとして着色され
  ます。
- 3 方向比較、アーカイブ内容の比較、移動したブロックの検出には対応していません。
