**HTML Merge** сравнивает две папки или два файла рядом — как WinMerge, но в виде одного
HTML-файла, который работает в любом современном браузере на Windows, macOS, Linux, ChromeOS,
Android и iOS. Выберите две папки — и появится список всех файлов обеих с тем, что с ними
произошло: идентичны, различаются, только слева, только справа. Откройте файл — и обе версии
встанут рядом, с подсветкой синтаксиса для более чем сорока языков, изменёнными словами,
отмеченными внутри изменённых строк, и картой всех различий рядом с полосой прокрутки.

Только чтение. Ничего не устанавливается, ничего не загружается на сервер, и ни один файл
никогда не изменяется: файлы читает сама страница, в браузере, и страница вообще не может
обратиться к сети.

Та же страница работает и как PWA (Progressive Web App): размещённая на GitHub Pages, она может
быть установлена в систему и затем работает как отдельное приложение — со своим окном и
значком — и работает офлайн — см. «[GitHub Pages](#github-pages)».

## Как пользоваться

1. Соберите `build/html-merge.html` (см. «[Сборка](#сборка)») или возьмите его из релиза и
   откройте в браузере — подойдёт прямо с диска.
2. Выберите левую и правую стороны: **Папка…** или **Файл…** для каждой, либо перетащите папку
   или файл в соответствующее поле. Две папки или два файла, перетащенные на окно одновременно,
   сравниваются сразу.
3. **Сравнить**.

При выборе двух папок появляется список папок, который заполняется по мере сравнения файлов.
Чипы сверху показывают или скрывают каждый вид результата и считают их; список может быть
деревом или плоским списком путей, фильтроваться по имени (`util` или по шаблону вроде `*.ts`)
и сортироваться по любому столбцу. Двойной щелчок по файлу (или выделение и нажатие Enter)
сравнивает его; `]` и `[` переходят к следующему и предыдущему отличающемуся файлу, а Esc или
кнопка «Назад» браузера возвращают к списку.

На экране файла:

- стрелки перемещают между различиями (Alt+↓ и Alt+↑, либо F7 и Shift+F7); текущее отмечено на
  полях, а карта справа показывает, где находятся все остальные — щёлкните по ней, чтобы
  перейти;
- **Рядом или один под другим** переключает между двумя панелями и одной объединённой;
- **Свернуть одинаковые строки** скрывает длинные одинаковые участки, оставляя несколько строк
  вокруг каждого различия; щёлкните свёрнутый участок, чтобы раскрыть его;
- **Найти** (Ctrl+F, ⌘F на Mac) отмечает каждое совпадение с обеих сторон; Enter и Shift+Enter
  перемещают между ними;
- меню **⋯** содержит параметры вида и сравнения: расположение, язык для подсветки файлов,
  цвета синтаксиса, видимые пробелы и концы строк, слова или символы внутри изменённых строк и
  что игнорировать.

Изображения (PNG, JPEG, GIF, WebP, BMP, ICO, AVIF) показываются рядом с указанием размера в
пикселях. Остальные двоичные файлы сравниваются побайтово: страница сообщает, идентичны ли они,
где находится первое различие, и показывает байты вокруг него.

Chrome и Edge запоминают недавние сравнения: они перечислены на начальном экране и открываются
снова одним щелчком (браузер ещё раз спросит разрешение на чтение папок). Другие браузеры
каждый раз выбирают папки заново.

### На телефоне

Страница работает и на экране телефона: начальный экран располагает обе стороны друг под
другом, список папок оставляет имя и результат, а пара файлов показывается один под другим.
Коснитесь файла, чтобы открыть его. На Android Chrome выбирает и папки, и файлы; iOS может
сравнивать файлы (папки там выбрать нельзя).

## Возможности

- **Папки**: рекурсивное сравнение по содержимому (или, быстрее, по размеру и дате); дерево или
  плоский список; фильтры по результату и по имени; сортировка по имени, результату, размеру
  или дате; имена, исключённые по шаблону (`.git; node_modules; *.log; build/`); имена файлов
  сравниваются с учётом регистра или без; статусы заполняются по мере чтения файлов, по
  несколько за раз, так что даже большие папки сразу что-то показывают.
- **Текст**: patience-алгоритм поверх алгоритма Майерса, поэтому перемещённые скобки и пустые
  строки не связывают между собой несвязанный код; строки изменённого блока сопоставляются по
  степени схожести; изменённые слова или символы отмечаются внутри строки; блоки пустых строк
  можно игнорировать; объединённый вид; свёртывание одинаковых строк; поиск по обеим сторонам.
- **Параметры сравнения**: игнорировать изменения пробелов или все пробелы, игнорировать
  регистр, игнорировать пустые строки, игнорировать концы строк (CRLF, LF, CR) — как для списка
  папок, так и для экрана файла.
- **Кодировки**: UTF-8, UTF-8 с BOM, UTF-16 LE и BE, а также Windows-1252 для файлов, которые не
  являются корректным UTF-8; для каждой стороны показываются кодировка, концы строк и
  количество строк, а различие только в концах строк называется именно так.
- **Подсветка синтаксиса** для более чем сорока языков, определяемых по имени файла или его
  первой строке (`#!/usr/bin/env python3`): JavaScript, TypeScript, JSON, HTML (со скриптами и
  стилями внутри), XML, CSS, SCSS, Less, Markdown, Python, Java, Kotlin, C, C++, C#, Go, Rust,
  Swift, Objective-C, PHP, Ruby, shell, PowerShell, batch-файлы, SQL, YAML, TOML, INI,
  Dockerfile, Makefile, CMake, diff, Lua, Perl, R, Dart, Scala, Groovy, Haskell, Elixir,
  GraphQL, Protocol Buffers, Pascal, Visual Basic. Любой другой язык можно выбрать вручную.
- **Большие файлы**: отрисовываются только видимые строки, поэтому файлы из сотен тысяч строк
  прокручиваются плавно; очень длинные строки обрезаются на экране (при сравнении они всё равно
  учитываются целиком).
- **Изображения и двоичные файлы** — как описано выше.
- **Семнадцать языков** интерфейса, справа налево для арабского и урду; светлая и тёмная темы,
  следующие за системой или выбираемые вручную.
- Установленное приложение обновляется только по запросу: см. «[GitHub Pages](#github-pages)».

## Комбинации клавиш

| Клавиши | Действие |
| --- | --- |
| Alt+↓, F7 | Следующее различие |
| Alt+↑, Shift+F7 | Предыдущее различие |
| `]` / `[` | Следующий / предыдущий отличающийся файл |
| Ctrl+F (⌘F) | Поиск в файлах или фильтр списка папок |
| Enter / Shift+Enter | Следующее / предыдущее совпадение |
| ↑ ↓ ← → | Перемещение по списку папок, открытие и закрытие папок |
| Enter | Открыть выбранный файл |
| Esc | Назад к списку папок |
| F5 | Сравнить снова |
| ? | Список комбинаций клавиш |

## Безопасность

- **Только чтение.** Страница читает файлы и никогда не записывает, не переименовывает и не
  удаляет ничего. В Chrome и Edge папки открываются через File System Access API только с
  доступом на чтение.
- **Офлайн по устройству.** Content-Security-Policy страницы указывает `connect-src 'none'`, и
  всё необходимое — стили, код, значки — находится внутри одного HTML-файла. Она не может
  ничего загрузить или отправить, что бы ни содержал сравниваемый файл.
- **Закреплённый скрипт.** Сборка заменяет `script-src 'unsafe-inline'` на хеш единственного
  скрипта на странице: если имя файла или строка текста когда-либо проскочат
  неэкранированными, встроенный обработчик в них всё равно не выполнится. Текст из файлов
  попадает на страницу уже экранированным.
- Недавние сравнения (Chrome и Edge) хранят в IndexedDB браузера только дескрипторы папок — без
  имён файлов и содержимого внутри. Настройки хранятся в `localStorage`.

## Переводы

Интерфейс говорит на английском, китайском, хинди, испанском, французском, арабском,
бенгальском, португальском, русском, урду, индонезийском, немецком, японском, маратхи,
телугу, турецком и украинском. Он запускается на первом из известных ему языков браузера;
Настройки → Язык выбирают другой.

- Английский живёт в коде: `t('context', 'English text')` или
  `tn('context', '{count} file', '{count} files', n)` для текста с числом. В
  `src/app/template.html` то же самое — `data-i18n="context"` (текст элемента) и
  `data-i18n-attr="context"` (его title, placeholder и aria-label).
- Каждый другой язык — это словарь, `src/locales/<code>.json`:
  `{ "context": { "English text": "translation" } }`. Текст с числом имеет по одной форме на
  каждую категорию множественного числа языка (`Intl.PluralRules`), с ключом по английской
  форме множественного числа.
- Всё, чего нет в словаре, показывается на английском.
- `npm run i18n` выводит для каждого языка строки, которых не хватает в его словаре, и те, что
  в нём есть, но интерфейс больше не использует; `npm test` проверяет плейсхолдеры и формы
  множественного числа.

## Сборка

Нужен Node.js 20 или новее.

```sh
npm install
npm run build        # build/html-merge.html and build/pages/
npm run watch        # rebuilds on every change
npm run check        # typecheck, unit tests, build, browser tests
```

`./build.sh` делает то же самое, что и `npm run build`, устанавливая зависимости при первом
запуске. Единственные зависимости — esbuild и TypeScript, обе только для сборки; сама страница
не использует никаких библиотек.

- `npm test` запускает модульные тесты в Node: сравнение, строки и свёртывание, кодировки,
  подсветку синтаксиса и её грамматики, сравнение папок, словари.
- `npm run test:browser` управляет собранной страницей и PWA в headless-Chrome через протокол
  DevTools, без других зависимостей. Нужен локальный Chrome или Chromium
  (`CHROME=/path/to/chrome`, чтобы выбрать конкретный) — при его отсутствии тест пропускается.
- `npm run shots -- <dir>` сохраняет снимки экрана каждого основного экрана.
- `npm run icons` создаёт PNG-значки PWA из `assets/icon.svg`.

## Версии и релизы

Версия хранится только в `package.json`. Сборка коммита с тегом `v<version>` показывает её как
есть; любая другая сборка добавляет свой коммит (`0.1.0+1a2b3c4`), поэтому страница, собранная
из `main`, не принимается за релиз. Версия показывается внизу начального экрана и в настройках.

Чтобы выпустить релиз: `npm version minor` (или `patch`), затем `git push --follow-tags`. Тег
запускает `.github/workflows/release.yml`, который проверяет, что тег совпадает с
`package.json`, запускает тесты и прикрепляет `html-merge-v<version>.html` и
`SHA256SUMS.txt` к релизу на GitHub.

## GitHub Pages

`build/pages/` — та же страница в виде устанавливаемого PWA: манифест, значки и service worker,
который сохраняет её работоспособность офлайн. `.github/workflows/pages.yml` собирает и
тестирует её и разворачивает на GitHub Pages при каждом push в `main` (Settings → Pages →
Source: GitHub Actions). Все её пути относительные, поэтому она работает по адресу `/<repo>/`
сайта проекта.

- CSP у PWA добавляет только свой собственный источник для манифеста, воркера и значков;
  `connect-src` остаётся `'none'`.
- Новое развёртывание само по себе не заменяет работающую версию: новый service worker ждёт, а
  в настройках (и на начальном экране) появляется «Версия X готова. Обновление». Страница тихо
  проверяет обновления каждые шесть часов и при восстановлении соединения.
- После обновления один раз появляется «Обновлено до версии X».

## Ограничения

- **Только чтение по замыслу**: нет ни слияния, ни редактирования; копируйте изменения в своём
  редакторе.
- Firefox и Safari выбирают папки через диалог загрузки папки браузера: он читает всю папку
  целиком (исключённые имена отсеиваются уже после, а не пропускаются), не показывает пустые
  папки, а обновление не видит файлов, добавленных с тех пор, — для этого нужно выбрать папки
  заново. iOS вообще не может выбирать папки.
- Файлы крупнее 64 МБ сравниваются только побайтово, без параметров игнорирования.
- Подсветка синтаксиса лексическая — ключевые слова, строки, комментарии, числа — а не разбор
  кода; некоторые конструкции (теги JSX, heredoc) окрашиваются как обычный текст.
- Нет трёхстороннего сравнения, нет сравнения содержимого архивов, нет обнаружения
  перемещённых блоков.
